# Issue 2：简化心理层标注 — MVP（修订版）

- 状态：`MVP_REVISED / READY_FOR_REVIEW`
- 优先级：P1
- 所属：ai-native 生态
- 目标：把难以严格执行的“三类证据门槛（语言模式／行为矛盾／情绪信号）”简化为可观察、可验证、可迭代的轻量标注。
- 风险声明：可能误标，但比漏标好；不替代心理咨询。

---

## 1. 背景

原设计把心理层标注简化为两类：

- `USER_ADMITS`
- `BEHAVIORAL_CONTRADICTION`

审查后需要补三个能力：

1. 明确“明显行为矛盾”的判定标准；
2. 增加“疑似”状态，避免非黑即白；
3. 建立验证机制，追踪标注准确率。

---

## 2. dbs 是怎么处理的（对照）

- `dbs-action`：用信号 A—F 识别心理阻力，主要靠语言模式和行为描述，没有严格的证据分级。
- `dbs-diagnosis`：有“心理问题信号”列表，规则是“同一信号最多提一次”，不强行插入。
- 结论：dbs 已经比“三类证据门槛”更轻，但没有显式区分“用户自己承认”和“明显行为矛盾”，也没有验证机制。

本 MVP 在 dbs 的轻量基础上，增加可执行标准和反馈闭环。

---

## 3. 修订后的 MVP

### 3.1 标注类型

| 标注 | 含义 | 触发条件 |
|---|---|---|
| `USER_ADMITS` | 用户明确承认心理卡点 | 用户原话直接承认，例如“我知道该做但就是不做”“我是在逃避”“我就是拖延” |
| `BEHAVIORAL_CONTRADICTION` | 用户说的话和描述的行为明显矛盾 | 至少满足一条明确行为矛盾标准（见下） |
| `SUSPECTED` | 证据不足但有可能 | 有语言线索，但没有达到 `USER_ADMITS` 或 `BEHAVIORAL_CONTRADICTION` 的明确标准 |
| `NONE` | 无证据 | 不标注，不猜测 |

### 3.2 `BEHAVIORAL_CONTRADICTION` 明确标准

至少满足以下一条：

| 标准 | 示例 |
|---|---|
| 时间矛盾 | 声称没时间，但每天娱乐/刷手机 > 1 小时 |
| 消费矛盾 | 购买 > 3 个课程/资料，但完成率 = 0% |
| 行动矛盾 | 声称想改变，但超过 1 周没有任何相关行动 |
| 方向矛盾 | 声称在找方向，但已经频繁更换 > 3 个方向且每个 < 2 周 |
| 学习矛盾 | 声称在学，但从不提问、不实践、不输出 |

### 3.3 置信度

每次标注必须带置信度：

```text
HIGH   ：证据非常明确，用户原话或行为可直接对应标准
MEDIUM ：证据较明确，但仍有解释空间
LOW    ：只有线索，适合 SUSPECTED
```

### 3.4 输出格式

```text
## 心理层标注
{USER_ADMITS / BEHAVIORAL_CONTRADICTION / SUSPECTED / NONE} (置信度: {HIGH/MEDIUM/LOW})
- 证据：{用户原话或具体行为}
- 建议：{如果为 NONE 可不写；否则给出最小下一步或转介}
```

示例：

```text
## 心理层标注
BEHAVIORAL_CONTRADICTION (置信度: HIGH)
- 证据：用户说“我很想做”，但已购买 5 个课程，完课率为 0%，且最近 2 周没有开始任何相关任务。
- 建议：先不要新增学习资料；选一个最小任务，今天完成 10 分钟。
```

### 3.5 规则

1. 只有出现明确证据时才标注 `USER_ADMITS` 或 `BEHAVIORAL_CONTRADICTION`。
2. 两类同时出现时，优先 `BEHAVIORAL_CONTRADICTION`。
3. 证据不足但有可能时，使用 `SUSPECTED + LOW/MEDIUM`，不要直接跳成确诊式结论。
4. 无法判断时写 `NONE`，不硬标。
5. 同一个信号最多提一次，不在对话中反复追问。
6. 保留心理咨询免责声明，不越界做治疗。

---

## 4. 验证机制

### 4.1 用户反馈

在输出标注后，如果场景允许，追加一句：

> 这个判断准不准？如果不对，告诉我哪里不对。

### 4.2 7 天跟踪

对 `USER_ADMITS` / `BEHAVIORAL_CONTRADICTION` / `SUSPECTED` 的案例，7 天后记录：

- 用户是否认可标注；
- 用户是否产生新的行动；
- 标注是否帮助了后续建议。

### 4.3 准确率追踪

建立简单记录：

```text
总标注数
用户确认准确数
用户否认数
未反馈数
准确率 = 确认准确数 / (确认准确数 + 否认数)
```

只用于迭代，不用于惩罚模型。

---

## 5. 验收标准

- [ ] 用户明确说“我知道该做但就是不做” → `USER_ADMITS`
- [ ] 用户说“我很想做”但已买 5 个课程、完课率 0% → `BEHAVIORAL_CONTRADICTION`
- [ ] 用户说“我可能有点拖延”但证据不足 → `SUSPECTED`
- [ ] 用户只陈述普通商业问题 → `NONE`
- [ ] 每个非 `NONE` 标注都带置信度
- [ ] 每个非 `NONE` 标注都尽量收集用户反馈
- [ ] 免责声明保留

---

## 6. 部署建议

1. **先跑起来**：不追求完美，先用当前 MVP 版本在真实对话中试运行。
2. **收集反馈**：记录标注准确性和用户反馈。
3. **迭代优化**：根据反馈调整“明显行为矛盾”的标准和置信度阈值。
4. **不要扩大范围**：本轮不做情绪信号识别，不做严格评分，不新增重型 schema/脚本。

---

## 7. 边界

- 本 MVP 是 ai-native 生态的设计文档，不直接改变 PublicCard 发布门。
- 不替代 `dbs-action` / `dbs-diagnosis` 的既有流程。
- 不把心理层标注作为正式诊断结论，只作为辅助信号。
