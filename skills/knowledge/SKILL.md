## 核心哲学

**不赌用户记得对、信得对。** 用户可能记错、可能信了过时的说法、可能把推测当事实。本子 skill 接管"验证与溯源"这件事：检索公开知识库、区分原始事实／归纳／推测／未知，证据不足时保留 `UNKNOWN`，不编造。


# skills/knowledge（子 skill）

## 何时加载

入口判模命中“要查具体信息、历史经验或相关对话”时加载。

典型信号：

- 用户问“X 是什么”“Y 怎么用”。
- 用户查询产品、配置、版本或官方文档。
- 用户想知道社区过去怎样处理过相似问题。

超出 AI／Agent／OpenClaw 社区范围的问题，不使用本子 skill的私域知识源。

## 前置守门

查询前先完成入口守门：

1. 安全红线优先转 `safety`。
2. 查询包含他人身份、私密原话、成员／消息标识、凭证或其他不必要敏感信息时，先最小化并安全重述；未通过时记为 `QUERY_PRIVACY_DENY`，原查询不得外发。
3. 涉及删除、覆盖、转账、全量发送或生产变更时，先 `STOP` 并确认。
4. 当前价格、政策、版本、官方号码、服务状态等动态事实必须在同一回合核验当前权威来源；历史聊天只提供线索。

高优先级门未通过时，不继续普通知识查询。

## 默认知识源：公开知识库（已成型，clone 即用）

本子 skill的默认知识源是公开仓库 **`ai-native-knowledge-base`**：

| 内容 | 状态 |
|---|---|
| 脱敏聊天语料（6,032 条，发送者 → `USER_NNN`，7 类敏感模式 0 残留） | 公开 |
| 候选池（1,415 条干净摘录，含来源引用） | 公开 |
| BM25 检索脚本 | 公开 |

默认检索方式（**不需要授权**，clone 知识库即可）：用知识库随附的 BM25 检索脚本检索候选池（`data/candidates-clean.jsonl`），脚本名与用法见该知识库的 `data/README.md`。

返回 `HIT` 时带 `score / id / question / excerpt / source`（快照 hash + 消息 ID + 发送者），可溯源但**不含原始正文**。返回 `MISS` 时按本子 skill MISS 处理。

调用者只需提供知识库在本机的路径（如 `AIHD_CANDIDATES_PATH` 或 `--candidates`）；不要求提供私域根目录或读取授权。

公开摘录不足以回答时，如实返回 `MISS`／`UNKNOWN`，**不得用模型记忆冒充私域原文**。

## 可选增强：私域原始对话（补全上下文时）

当公开候选的摘录不足以回答，且调用者**显式提供**私域知识源时，才使用 `$dbs-knowledge` 回读原始对话补全上下文。此路径才涉及"授权"：

- `$dbs-knowledge`：当前宿主可以发现并调用的外部 Agent Skill（上游 `dontbesilent2025/dbskill`，不随本包复制）；
- `source_root`：调用者显式提供或当前项目知识库导航明确登记的私域根目录；
- `read_permission`：对本轮查询目的和范围有效的读取权限；
- `SOURCE_OF_TRUTH.md`：知识库导航，说明原始文件、派生定位文件、完整性收据、版本和冲突规则；
- `snapshot_cutoff` / `integrity_receipt`：如导航提供则按其核对。

公开包不得内置 `source_root`、私域文件 hash、消息／成员标识或原始正文。不得把当前目录、用户目录、环境变量或历史会话猜成知识源。

## 宿主适配协议（本候选内部）

上游 `$dbs-knowledge` 只提供“知识库导航 → 原始文件”的 Agent 调用约定，不提供统一 CLI、API、输入 schema 或状态枚举。本候选由宿主 wrapper 执行以下前置核验和结果归一化；下列字段与状态属于本候选内部协议，不是上游返回合同。

宿主 wrapper 至少要持有：

```text
query
source_root（可选增强路径才需要；调用者显式提供）
read_permission（可选增强路径才需要）
risk_labels（privacy／dynamic／irreversible／high_risk）
```

wrapper 在调用后，必须把实际读取的来源类型、快照截止时间、证据边界和 1 个下一步归一化为本合同表中的内部结果状态。没有可调用的 `$dbs-knowledge`、无法绑定 source 或无法读回原始上下文时，内部状态为 `SOURCE_UNAVAILABLE` 或 `HOLD`，不得用模型记忆补齐。公开仓库的脱敏测试只验证这个内部协议的顺序和失败边界，不冒充宿主端到端集成。

以下情况返回 `SOURCE_UNAVAILABLE`，不模拟调用：

- 公开知识库不可检索（脚本缺失、候选池不可读）；
- `$dbs-knowledge` 不可发现（仅可选增强路径）；
- 没有显式私域知识源（仅可选增强路径）；
- 根目录或 `SOURCE_OF_TRUTH.md` 不存在、不可读或权限不符（仅可选增强路径）；
- 导航没有指向可复核的原始来源（仅可选增强路径）。

## 固定读取顺序（可选增强路径）

### 1. 先读知识库导航

先调用 `$dbs-knowledge` 读取 `SOURCE_OF_TRUTH.md`，只按导航定位本轮需要的少量文件。不要递归扫描整个私域目录，也不要把导航摘要直接当成答案。

### 2. 完整性预检

在搜索正文前，按导航实际声明的 manifest、validation、SHA-256 收据或版本规则核对：

- 原始快照；
- 派生定位文件；
- bytes、SHA-256、权限和快照截止时间；
- 原始文件与派生文件的绑定关系。

路径必须规范化后仍位于显式 `source_root` 内；软链越界、路径穿越、收据不可解析、hash 漂移、收据冲突或派生文件未绑定当前原始快照时，返回 `HOLD`。不得用旧摘要、模型记忆或另一个快照补齐。

同一目录中的自报 hash 只能证明内部一致性，不是防篡改信任根。只有调用者预先锁定、受控目录保存或其他独立渠道读回的 hash，才能支持“未被协同改写”的结论；没有独立锚点时标为 `SOURCE_DECLARED_INTEGRITY`，不得宣称完整性已经外部证明。

### 3. 导航指定的定位文件只做定位

使用导航指定的 locator、索引、局部 README 或其他派生文件查找少量候选。当前项目可能使用 normalized 文件，但这只是一个已登记的实现，不是本子 skill固定文件名。定位结果只能返回来源标识和必要的上下文线索，不能直接提供最终答案。

没有候选时返回 `MISS`。不要为凑答案扩大为无边界全盘搜索，也不要声称知识库命中。

### 4. 回读导航指定的原始文件与上下文

每个候选必须按同一来源标识回到导航指定的原始文件或快照：

1. 确认原始记录存在且未删除（若该知识库有删除标记）；
2. 读取足以理解语义的前后消息或同一线程上下文；
3. 检查引用的附件、链接或被回复消息是否可用；
4. 比较多条来源是否冲突；
5. 只保留解决当前问题必要的证据。

定位命中但原始记录缺失、正文已删除、附件不可读、上下文截断或冲突无法裁决时，返回 `HOLD / UNKNOWN`，不能根据派生文本回答。

### 5. 形成回答

回答按自然语言区分：

- **原始事实**：原始消息或当前权威来源可以直接支持；
- **跨消息归纳**：由多条来源综合形成，不冒充任何人的原话；
- **模型推测**：基于来源的解释或建议，明确不是知识库事实；
- **未知**：来源缺失、冲突、过期或当前无法核验。

最后只给 1 个最小下一步。机器 `PASS`、定位 `HIT` 或来源存在都不能写成用户问题已经 `RESOLVED`。

## 隐私与最小披露

- 默认不输出私域绝对路径、成员身份、消息／线程标识、群名、凭证或大段逐字原文。
- 需要引用时先脱敏，并缩到支持当前结论的最小片段。
- 不把原始消息复制到公开 Git、测试 fixture、普通日志或第三方检索请求。
- 不因用户询问“谁说的”就自动暴露身份；没有明确权限和必要性时，只报告来源类型与时效。
- `QUERY_PRIVACY_DENY` 后不得把原查询发送到外部来源；先请用户去除敏感信息后重述。

## 动态事实与高风险事实

私域历史对话不能单独证明当前价格、政策、版本、官方号码、服务状态或其他动态事实。此类结论必须在同一回合核验当前官方或权威来源并注明核验时间。

医疗、法律、金融、人身安全、凭证／安全配置和生产不可逆操作不能由历史聊天或纯模型推理给出确定性最终结论。根据风险进入 `VERIFY`、`ESCALATE`、`STOP` 或 `UNKNOWN`。

## MISS 处理

`MISS` 表示当前知识源没有找到可复核的相关对话，不表示问题不存在或已经解决。

只有同时满足下列条件，才给一个“试试就知道了”的最小实验：

- `risk = LOW`；
- 动作完全可逆；
- 结果能在短时间内观察；
- 不涉及隐私、凭证、安全、动态事实或生产不可逆操作；
- 能写清成功信号、停止条件和恢复方法。

最小实验只包含：

1. 一个最小动作；
2. 一个可观察的成功信号；
3. 一个立即停止条件；
4. 一个恢复方法。

条件不齐时不建议盲试，改为 `VERIFY`、`ESCALATE`、`STOP` 或 `UNKNOWN`。

## 内部结果

| 结果 | 含义 | 下一步 |
|---|---|---|
| `HIT` | 公开候选池命中（或已回读原始消息） | 回答并标清事实、归纳、推测和未知 |
| `MISS` | 没有可复核候选 | 仅在低风险条件齐全时给最小实验 |
| `SOURCE_UNAVAILABLE` | 知识库或 Skill、路径、权限不可用 | 告知依赖缺口，不模拟 |
| `HOLD` | hash、原始记录、附件、线程或冲突门未通过 | 停止该来源分支 |
| `VERIFY` | 动态或高风险事实需要当前核验 | 读取当前权威来源 |
| `ESCALATE` | 需要专业资格或更高权限 | 交给合适的人 |
| `STOP` | 安全或不可逆门未通过 | 暂停动作 |
| `UNKNOWN` | 当前证据不足 | 说明缺口，不补造 |

这些是内部裁决词。对用户用自然语言说明，不倾倒机器标签。

## 输出所有权

- 完整答案，或明确的不可用／暂停／未知状态；
- 实际依据的来源类型和快照时效；
- 1 个最小下一步。

不分析心理动机，不发布标准答案，不把聊天观点漂白成事实，不把定位命中写成用户问题已解决。

## 失败规则

- 合同缺失：模块暂不可用，不模拟。
- 公开知识库不可检索：`SOURCE_UNAVAILABLE`。
- `$dbs-knowledge` 不可发现（可选增强路径）：`SOURCE_UNAVAILABLE`。
- 私域源未显式提供或权限不足（可选增强路径）：`SOURCE_UNAVAILABLE`。
- hash／版本绑定失配：`HOLD`。
- 派生命中但原始消息或上下文无法复核：`HOLD / UNKNOWN`。
- `MISS`：只按本子 skill的低风险最小实验条件继续。
- 用户问“为什么”：需要因果分析时转 thinking。
- 用户说“做不动”：转 action。
- 用户触红线：转 safety。
