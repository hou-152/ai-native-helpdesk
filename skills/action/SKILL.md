# skills/action（子 skill）

## 核心哲学

**不赌用户知道下一步。** "做不动"往往不是意愿问题，而是不知道第一步是什么、不知道卡点在哪。本子 skill 接管"给下一步"这件事：一次一个主要去向，**可观察、可回滚**，不把现实约束诊断成意愿问题。

> 「最小下一步」里的"最小"是伪概念——关键不是"小"，是**做完能看出结果（可观察）、错了能退回（可回滚）**。一个稍大但可观察可回滚的动作，好过一个很小但做完不知道有没有用的动作。

## 何时加载

用户知道要做什么但卡在启动、执行或验证，或者直接要求“下一步做什么”时加载。用户不知道目标或处理路径，且缺失信息确实会改变路径时转 good-question；用户要查事实时转 knowledge。

## 先响应实际请求

- “我今天要发一篇文章” → 先拆一个可观察的动作。
- “我做不动” → 已知信息足够时先给更小动作；只有卡点位置会改变动作时才问 1 个问题。
- “我没时间／资源／权限／身体条件” → 缩小、替代、等待或停止，不把现实约束诊断成意愿问题。

一次只给一个主要去向，不用行动清单覆盖用户场景。

## 下一步的两条硬标准

给出的动作必须同时满足：

1. **可观察**：做完后能明确知道“有没有用”（有指标、有信号、有可判断的结果）。
2. **可回滚**：错了能退回，不造成不可逆后果。

不满足时，缩小动作或换成 `VERIFY`／`WAIT`／`STOP`。

## 回合去向

内部必须保存下列 8 种状态之一；对用户只说右栏自然语言含义，不倾倒机器标签。

| 内部状态 | 适用情况 | 对外表达示例 |
|---|---|---|
| `DO` | 可以安全执行一个可观察、可回滚的动作 | “下一步先做这一件事……” |
| `VERIFY` | 先核实事实或结果再继续 | “先核实这一点再下结论……” |
| `WAIT` | 需要等待外部条件 | “现在先等这个条件出现……” |
| `STOP` | 当前动作风险过高、越界或已不值得继续 | “先停下当前动作……” |
| `NO_ACTION_NEEDED` | 理解或消解已经足够 | “这一步不用继续行动……” |
| `NEEDS_INPUT` | 一个缺失事实会改变路径 | “还差一个会改变处理路径的信息……” |
| `UNKNOWN` | 两次区分后或证据不足仍无法判断 | “目前证据不足，先保留未知……” |
| `ESCALATE` | 需要 Owner、有权限者或专业人士 | “这需要交给有权限或专业资格的人处理……” |

去向必须有用户可理解的具体内容。解释不能代替去向，也不能为了“有动作”强迫用户执行。

## 输出所有权

- 先回应用户当前卡点。
- 给一个主要去向和**可观察、可回滚**的一步。
- 只有缺失信息会改变处理路径时，附 1 个区分问题。

不诊断用户为什么做不动，不列 3—5 个原因让用户选，不用标准模板覆盖具体约束。

## 输出模板

- 当前判断：用自然语言说明本回合的一个主要去向与依据。
- 最小下一步：仅当去向为 `DO` 时，给出可观察、可回滚的一步；其他去向明确说明等待、停止、核验或补充什么。
- 验证信号：`CONFIRMED`／`EXCLUDED`／`UNKNOWN` 之一，并说明本次处理确认了什么、排除了什么，或仍缺少什么证据。
- 落库候选：`YES`／`NO`，标记本回合是否出现值得沉淀的新经验、新坑或规律；只标记，不写入任何候选池或资料库。

## 工具链

- 必备：无外部工具、API 或外部 skill。本子 skill 可仅按本文件的 8 种去向完成判断。
- 可选：Node.js 20+ 可运行 [`scripts/next-step.mjs`](scripts/next-step.mjs) 复现判定骨架；触发红线时按同级 `aihd-safety` 的守门规则处理。
- 降级：Node.js 或脚本不可用时，人工按「回合去向」表判断并保留 `UNKNOWN`；红线、权限不足或不可逆风险不能降级为 `DO`。

最小脚本只接受 `--input '<JSON>'`。例如：

```bash
node scripts/next-step.mjs --input '{"action":{"available":true,"observable":true,"reversible":true}}'
```

`--input '{}'` 会返回一个正常的 `UNKNOWN` 结构化结果；缺少或非法 `--input` 会在 stderr 输出单一 JSON 并以非零状态退出。

## 失败规则

- 用户不知道目标，且缺失信息改变路径：转 good-question。
- 用户问根因：转 thinking。
- 用户要查具体事实：转 knowledge。
- 用户触发红线：转 safety。
- 正确结果是等待、停止或无需行动时，不强行改写成 `DO`。
