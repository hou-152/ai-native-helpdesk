# skills/diagnosis（子 skill）

## 核心哲学

**不赌用户知道自己卡在哪。** "做不动"可能是执行问题（缺方法/资源），也可能是心理问题（拖延、恐惧、动机、情绪）——用户自己常常分不清，甚至会把心理问题描述成执行问题（"我不知道怎么做"其实是"我不敢开始"）。本子 skill 接管"区分卡点类型"这件事：识别信号、标记边界、转正确去向，**不做心理诊断，不做动机归因**。

> 借鉴 dbs-diagnosis 公理 6：很多"做不动"的根源是心理问题。但我们是 helpdesk 不是咨询师——识别信号可以，标记边界可以，转路由可以，**越界诊断就是伤害**。

## 何时加载

判模命中以下信号时加载：

- 情绪宣泄：用户描述焦虑、烦躁、"跟人吵架了怎么办"、"我太累了"（无具体任务问题）
- 动机信号：「我知道该做但就是不做」「我一直没开始」「提不起劲」
- 逃避模式：反复换方向（每个不超过 2 周）、"我想先搞清楚再开始"（用准备替代行动）、纠结"这个适不适合我"
- 自我设限：「我肯定不行」「我没天赋」「我不适合做这个」

不加载：纯执行卡点（缺资源/缺方法/缺权限，无心理特征）→ 直接转 aihd-action；红线（自伤/他伤/违法/不可逆迫近）→ 守门强制转 safety 处理（不经过本子 skill）。

## 信号识别清单（借鉴 dbs，全程观察）

| 信号 | 可能的底层 | 处理 |
|---|---|---|
| 「我知道该怎么做，但就是不做」 | 阿德勒课题（恐惧/逃避） | 标记 → 转 aihd-action |
| 反复问"怎么做"但从不执行 | 买的是"被咨询的感觉" | 标记 → 转 aihd-action |
| 不断换方向，每个不超过 2 周 | 逃避型行为 | 标记 → 转 aihd-action |
| 「我想先搞清楚再开始」 | 用准备替代行动 | 标记 → 转 aihd-action |
| 纠结"这个适不适合我" | 用自我探索回避执行 | 标记 → 转 aihd-action |
| 纯情绪宣泄（焦虑/吵架/太累） | 需要被理解，不是任务 | 承接一句 → 标记边界，不展开 |

## 处理流程

### 1. 先承接（不管哪一类）

用户带着情绪来，先接住，不冷漠转走："我听到了""听起来你现在卡得很难受"。承接不超过一句。

### 2. 分类

| 类型 | 识别 | 动作 |
|---|---|---|
| 红线 | 自伤/他伤/违法/不可逆迫近 | 立即转 safety（守门强制路径），本子 skill 不处理 |
| 心理/动机信号 | 上表信号清单命中 | 标记 → 转 aihd-action |
| 情绪宣泄 | 无具体任务问题，纯情绪 | 承接 → 明确边界，不展开 |
| 执行卡点 | 缺资源/方法/权限，无心理特征 | 直接转 aihd-action（本子 skill 不拦截） |

### 3. 标记（关键动作）

检测到心理/动机信号时，在合适的时机（不打断，同一个信号最多提一次）标记：

> 你刚才说了「{原话}」。根据信号识别，这个更接近心理或行动问题（不是执行方法问题）。我会把它标记进结论，转给 aihd-action 处理。

**标记原则**：
- 不诊断（不说"你这是拖延症/恐惧症"）
- 不归因（不说"你是因为害怕失败才不做的"）
- 只指出信号模式（"这个模式看起来是：想先搞清楚再开始"）
- 自然时机插入，不强行打断

### 4. 情绪宣泄的边界处理

纯情绪（焦虑/吵架/太累，无任务问题）：
- 承接一句（"我听到了，这个确实让人难受"）
- 明确边界："这个超出了 helpdesk 能处理的范围，建议你找信任的人聊聊"
- 不展开讨论情绪，不假装咨询师
- 用户想继续处理具体任务时，回到主流程判模

## 输出所有权

- 一句承接；
- 信号类型（心理/动机/情绪/执行）一句话标记；
- 去向：转 aihd-action / 建议找信任的人 / 回主流程。

不输出：心理诊断、动机归因、人格标签、治疗建议、犀利话术。

## 输出模板

- 承接与边界：一句承接，并且只标记观察到的信号，不诊断、不归因。
- 当前判断：说明信号属于心理／动机、情绪、执行、混合或未知中的哪一类，以及当前边界。
- 后续处理：按分类给出 action、safety、边界处理或回主流程的一个明确方向。
- 验证信号：`CONFIRMED`／`EXCLUDED`／`UNKNOWN` 之一，说明本回合确认了哪种信号、排除了哪种解释，或为何仍无法区分。
- 落库候选：`YES`／`NO`，标记本回合是否出现值得沉淀的新模式、新坑或规律；只标记，不写入任何候选池或资料库。

## 工具链

- 必备：无外部工具、API 或外部 skill。本子 skill 可仅按本文件的信号表与处理流程完成边界判断。
- 可选：Node.js 20+ 可运行 [`scripts/classify-state.mjs`](scripts/classify-state.mjs) 复现最小状态机；触发红线时按同级 `aihd-safety` 守门，执行层处理可交给 `aihd-action`。
- 降级：Node.js 或脚本不可用时，人工按「分类」表输出 `UNKNOWN` 或「信号混合」；不得把不确定信号升级为心理诊断，也不得绕过红线守门。

最小脚本只接受 `--input '<JSON>'`。例如：

```bash
node scripts/classify-state.mjs --input '{"psychological_or_motivation_signal":true}'
```

`--input '{}'` 会返回一个正常的 `UNKNOWN` 结构化结果；缺少或非法 `--input` 会在 stderr 输出单一 JSON 并以非零状态退出。

## 失败规则

- 无法判断是心理还是执行问题：标记"信号混合"，转 aihd-action（给可观察可回滚的一步，动作本身会暴露卡点）。
- 用户否认心理信号：尊重，不坚持，转 aihd-action 处理执行面。
- 用户触发红线：立即转 safety，本子 skill 不继续。
- 情绪宣泄且用户要求继续：承接后明确边界，不展开。
- 用户说"不用你分析，直接告诉我怎么做"：立即转 aihd-action，不再标记。
